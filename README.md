# GitHub Achievements: Practical Guide

A practical, community-first guide to GitHub profile achievements: what they recognize, how to make legitimate progress, and which historical badges are no longer obtainable.

> **Important:** GitHub controls achievement eligibility and may change its rules. This repository is an educational guide, not an achievement-unlocking tool. Never use spam, fake collaboration, or low-quality pull requests just to chase badges.

## What are GitHub achievements?

Achievements are profile badges that recognize certain activities on GitHub. Depending on the achievement, progress may involve repository stars, merged pull requests, accepted Discussion answers, collaboration, reactions, or using GitHub development tools. GitHub awards them automatically when its criteria are met.

## Achievement guide

### 🌟 Starstruck
Recognizes repositories that receive stars. Build something useful, write a clear README, add screenshots or a demo, maintain the project, and share it with communities where it is relevant. Stars are earned from genuine interest; they cannot be guaranteed.

### 👯 Pair Extraordinaire
Recognizes qualifying pull-request collaboration with a co-author. Work with another developer on a real change, use Git's `Co-authored-by:` trailer with the collaborator's GitHub-associated email, and get the pull request merged. Follow GitHub's current eligibility rules.

Example commit message:

```text
Add accessible navigation menu

Co-authored-by: Collaborator Name <verified-email@example.com>
```

### 🤠 Quickdraw
Recognizes an issue or pull request that is closed very soon after it is opened (commonly described as within five minutes). Use this only when there is a genuine reason to open and close an issue or PR; avoid creating noise in other people's projects.

### 🦈 Pull Shark
Recognizes merged pull requests. Contribute useful fixes, tests, accessibility improvements, documentation, or features. Start with issues labelled `good first issue` or `help wanted`, read `CONTRIBUTING.md`, and respond constructively to review feedback. Only merged PRs that meet GitHub's criteria count.

### 🧠 Galaxy Brain
Recognizes answers accepted in GitHub Discussions. Find questions in projects you understand, give accurate and complete answers, add minimal reproducible examples where useful, and link to authoritative documentation. The discussion owner or maintainer decides whether an answer solves the question.

### 😎 YOLO
Associated with merging a pull request without a review. Do not bypass review in production or shared projects to obtain a badge. If exploring this achievement, use a disposable personal test repository and understand the risks first.

### 🧙 Open Sourcerer
Recognizes qualifying contributions across open-source projects. Focus on meaningful contributions to multiple repositories, such as bug fixes, tests, translations, documentation, and accessibility. Check the achievement detail on your own profile for the current criteria and progress.

### ❤️ Heart On Your Sleeve
Associated with using the heart reaction on GitHub content. React naturally to an issue, pull request, or discussion you genuinely appreciate. Do not mass-react or spam.

### 👾 Codecrafter
Associated with creating and merging a pull request using GitHub Codespaces. For a real contribution, open a Codespace, create a branch, make and test a change, and submit a pull request that is accepted and merged. Check the badge details on your profile for current eligibility.

### 🔍 Public Sponsor
Associated with publicly sponsoring an eligible open-source maintainer through GitHub Sponsors. This may require spending money; sponsorship should be voluntary and based on supporting work you value. Make sure you understand the payment and visibility settings before sponsoring.

## Historical achievements

### 🧊 Arctic Code Vault Contributor
This was tied to the GitHub Archive Program snapshot from February 2020. It is a historical achievement and cannot be newly earned through ordinary contributions today.

### 🚁 Mars 2020 Helicopter Contributor
This was awarded for commits to a specific set of repositories and versions used in the Mars Ingenuity helicopter project. GitHub states that the event has ended, so this badge is no longer available to earn.

## A realistic action plan

1. **Check your current profile.** Visit [your GitHub profile](https://github.com/zain-khan-pro) and inspect the Achievements section to see what you already have and any progress shown.
2. **Improve one useful project.** Add a clear problem statement, installation steps, screenshots, examples, tests, and contribution instructions.
3. **Contribute to real open-source issues.** Choose projects you use or understand; submit small, reviewable improvements.
4. **Help people in Discussions.** Answer questions you can genuinely solve and include reliable references.
5. **Collaborate.** Pair with a real contributor on a useful change and follow the project's review process.
6. **Recheck badge details.** GitHub's own achievement tooltip and official documentation take precedence over third-party guides.

## Show achievements on your profile

1. Open GitHub and go to **Settings**.
2. Under **Profile settings**, find **Show Achievements on my profile**.
3. Enable it and save the preference if needed.

You can also hide individual achievements from your public profile. The badge itself and its visibility are controlled by GitHub, not by this repository.
